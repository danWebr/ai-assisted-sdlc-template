name: implement
description: "Implement a piece of work based on a spec or set of tickets."
disable-model-invocation: true
---

Unless the user explicitly requests a different approach, use the default delivery workflow:

1. Choose the delivery route and branch before editing. For ordinary implementation work invoked on `dev`, fetch `origin dev` and verify that `origin/dev` resolves; if it does not, stop and report the missing branch. If the working tree is not clean, stop and report the blocking files before changing branches. Fast-forward local `dev` to `origin/dev` with `git merge --ff-only`, then create and switch to a focused branch from `origin/dev`. Use a prefix matching the change type, such as `feat/`, `fix/`, `docs/`, or `chore/`; include `<ticket>-` when a ticket exists, otherwise use `<short-description>`. Check both local and `origin` for the target branch before creating it; if either already exists, stop and report it. On an existing non-protected topic branch, stay on that branch and do not silently create a second branch. On `main` or another protected branch, stop unless the user explicitly requests a compatible repository-approved workflow. For an approved hotfix on `main`, fetch `origin main`, verify that `origin/main` resolves, fast-forward local `main`, and create a `hotfix/` branch from `origin/main`; target its pull request at `main`, and leave synchronization of the merged hotfix back into `dev` to the human release workflow. Stop on a detached `HEAD` or an otherwise unknown protected branch. Never commit or push directly to `dev` or `main`.
2. Implement the work described by the user in the spec or tickets. Use tdd where possible, at pre-agreed seams. Run typechecking and focused tests regularly. The implementation stage is complete only when the intended behavior is implemented and the focused checks are green.
3. Prepare and review a candidate commit. Run `mise run verify` and `git diff HEAD --check` before staging. Stage the implementation, run `git diff --cached --check`, and commit it with a Conventional Commit. Then run `git diff <delivery-base>...HEAD --check` and invoke `code-review` with `<delivery-base>` as its fixed point plus the originating ticket or spec path/URL; if no spec exists, state that explicitly. Address actionable findings, rerun the checks, commit the fixes, and repeat the range check and review until the current commit range has no actionable findings.
4. Push the reviewed feature branch to `origin` with upstream tracking. Open a pull request to the approved delivery target (`dev` for the default route, `main` for an approved hotfix, or the explicitly approved target), using `.github/PULL_REQUEST_TEMPLATE.md` and including the ticket when one exists, summary, `mise run verify` and `git diff <delivery-base>...HEAD --check` evidence, operational impact, and agent assistance.
5. Wait for every required pull-request check to complete. For any non-infrastructure failure, including code, tests, lint, documentation, workflow syntax, or repository verification, inspect the failure and make the smallest fix. Rerun the affected checks, `mise run verify`, and `git diff HEAD --check`; stage the fix, run `git diff --cached --check`, commit it, rerun `git diff <delivery-base>...HEAD --check` and `code-review` with the same delivery base and spec source, push, and wait again. If the failure is infrastructure, permissions, cancellation, timeout, or still present after one repair, stop and report it for human intervention. Finish only when every required check has passed; never merge the pull request.

If the user explicitly specifies another base branch, branch strategy, commit-only handoff, pull-request target, or review/CI approach, substitute it for the corresponding default stage only when it remains compatible with `AGENTS.md`, protected-branch rules, `mise run verify`/`Verify`, and human review and merge requirements. A commit-only handoff ends after the reviewed commit; it does not push, open a pull request, or monitor CI. If an override conflicts with those invariants, stop and report the conflict.
