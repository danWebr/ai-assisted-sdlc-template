# Agent compatibility and platforms

## Pi — primary and tested

Pi loads the canonical `AGENTS.md`, discovers the project-local skills under `.agents/skills/` after the repository is trusted, and installs the unpinned [`pi-subagents`](https://github.com/nicobailon/pi-subagents) and `pi-web-access` packages declared in `.pi/settings.json` through its normal trust flow. Review those package sources before trusting the project. Canonical workflows use `pi-subagents` roles such as `reviewer`, `scout`, `delegate`, and `researcher`; compatible runtimes use their equivalent facilities. Provider, model, authentication, reasoning level, and UI settings stay in user configuration and are never generated by this repository.

Skill commands are available as `/skill:<name>`. The project has been designed for interactive Pi use; no hosted or unattended agent is implied.

## Codex — compatible, not equivalently tested

Codex reads `AGENTS.md` and discovers repository skills under `.agents/skills/`, so no adapter or duplicate skill source is needed. Invoke a skill explicitly through Codex's skill selector when automatic matching is inappropriate. Codex permissions, models, and personal configuration remain user-local.

Official references: [Codex `AGENTS.md`](https://learn.chatgpt.com/docs/agent-configuration/agents-md) and [Codex skills](https://learn.chatgpt.com/docs/build-skills).

## Claude Code — thin compatibility adapters

Claude Code reads `CLAUDE.md`, which imports the canonical `AGENTS.md`. Claude discovers project skills under `.claude/skills/`, so each entry there contains only metadata and an instruction to load the matching canonical `.agents/skills/<name>/SKILL.md`. Changes belong in the canonical directory; adapters must not grow independent workflow content.

Official references: [Claude Code project instructions](https://code.claude.com/docs/en/memory#agentsmd) and [Claude Code skills](https://code.claude.com/docs/en/skills).

## Supported local platforms

macOS is the tested golden path. Ubuntu should work with adaptations to package-manager commands, executable locations, shell packages, and browser-based CLI authentication, but end-to-end Linux support is not claimed. Native Windows is outside the supported scope; WSL may follow the Ubuntu notes but is not tested as a separate platform.

This repository documents a personal workflow for incidental public reuse. Compatibility guidance is best-effort and is not a community support commitment.

### macOS golden-path setup

The tested path uses a current macOS release with the system `zsh` and
`/usr/bin/script`. Install each prerequisite from its upstream source; this
repository intentionally does not install or pin user-level tools.

1. Install Apple's Command Line Tools with `xcode-select --install`, open a new
   terminal, and confirm `git --version` succeeds.
2. Install the current Node.js LTS from the official
   [Node.js download](https://nodejs.org/en/download), then install Pi from its
   [official quickstart](https://github.com/badlogic/pi-mono/blob/main/packages/coding-agent/docs/quickstart.md):

   ```sh
   npm install -g @earendil-works/pi-coding-agent
   pi --version
   ```

3. Install `mise` using its recommended
   [macOS installer](https://mise.jdx.dev/installing-mise.html), activate it for
   `zsh` as described in the
   [getting-started guide](https://mise.jdx.dev/getting-started), open a new
   terminal, and run `mise doctor`.
4. Install `jq` and GitHub CLI from their official macOS guidance. Homebrew is
   the tested package manager:

   ```sh
   brew install jq gh
   gh auth login
   ```

   If Homebrew is not already installed, review its installer at
   [brew.sh](https://brew.sh/) first. The authoritative alternatives are the
   [`jq` download guide](https://jqlang.org/download/) and
   [GitHub CLI installation guide](https://github.com/cli/cli#installation).
5. If the project will use Railway, install its CLI with agent support using
   Railway's current [official CLI setup](https://docs.railway.com/cli), then
   run `railway login`. Do not install a copied or vendored Railway skill.
6. Before using a generated project, confirm the local contract's commands are
   available:

   ```sh
   command -v git mise jq script gh pi
   command -v railway  # required only when Railway was selected
   ```

7. Create and clone a repository through **Use this template**. In that clone,
   inspect `AGENTS.md`, `.pi/settings.json`, and the project-local skills before
   trust; run `mise run verify`; run `mise run bootstrap`; review and manually
   commit its uncommitted diff; then run `mise run provision`. Start Pi, accept
   project packages only after reviewing their sources, use `/login` for the
   chosen provider, and begin product discovery with
   `/skill:grill-with-docs`.

The `script` pseudo-terminal utility used by provisioning acceptance is part of
macOS; it is not the same as the repository's shell scripts. Ubuntu users must
adapt the package-manager commands and may need the `util-linux` implementation
of `script`. Browser authentication and executable paths can also differ.
